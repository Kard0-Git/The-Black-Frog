Lab 1: SSH, Static Pages, and Your First Dynamic Server

Department of Computing

Autumn Term

Learning goals

By the end of this lab you will be able to:

  • Connect to a remote Unix server over SSH
  • Publish a static web page from your home directory using public_html
  • Provision and configure your own personal virtual server
  • Run a minimal Python static file server to serve files over port 80
  • Explain the difference between a static page (served as-is from disk) and a dynamic page (generated by a running program on each request)
  • Run a minimal Python program that generates HTML dynamically

Part A: The shared department server

A1. Connect over SSH

From a terminal:

ssh username@doc.gold.ac.uk

Replace username with your own intranet username. Enter your password when prompted.

Need a refresher on SSH keys and remote shells? Check out DigitalOcean’s SSH Essentials Guide or the MDN Guide to SSH Keys.

A2. Create your public web folder

Every user has a special folder, public_html, which Apache automatically serves at a personal URL.

mkdir public_html
chmod 755 public_html

Why 755, not 644? A directory needs its execute bit set for anyone to be able to look inside it (cd into it or have Apache read files from it). 755 (rwxr-xr-x) means: you can read/write/enter it, everyone else can only read/enter it. 644 is the right permission for the file you’re about to create inside it — files don’t need to be “entered,” just read.

Deep dive on Unix permissions: - Experiment with the interactive Chmod Calculator to see visual bitwise breakdowns (r = 4, w = 2, x = 1). - Read Red Hat’s Linux File Permissions 101 to understand chmod, chown, and octal notation. - Read the MDN 403 Forbidden Explained documentation to see how web servers respond to OS-level permission failures.

A3. Create a basic page

cd public_html
nano index.html

Paste in a minimal page:

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>My First Page</title>
</head>
<body>
  <h1>Hello from the shared server!</h1>
  <p>This is a static page — it never changes unless I edit the file.</p>
</body>
</html>

Save and exit, then set the file permission:

chmod 644 index.html

A4. View it in a browser

Visit your department URL:

<https://doc.gold.ac.uk/~username/>

(Replace username with your own login name).

Checkpoint: If you see your page, Apache is correctly serving from public_html. If you get a 403 Forbidden, double-check the permissions in A2/A3 — this is the single most common mistake.

Part B: Your own personal virtual server

The shared server is fine for static files, but you don’t have admin rights on it — so you can’t install software or bind background programs to ports. For this and future labs, you’ll use your own personal virtual server, where you have full root access.

Rather than dealing with the overhead and configuration files of Apache, we will use Python’s built-in HTTP server to serve your static files directly.

B1. Create the server

  1. Go to the Virtual Server Manager: https://www2.doc.gold.ac.uk/dept/VirtualServer
  2. Fill in the form:
    • Server ID — pick a free numeric ID (0–999)
    • Admin Username — pre-filled with your intranet username
    • Admin Password — set this now (unlike the CLI, the form lets you set it directly)
    • Operating System — e.g. ubuntu26
    • System Type — choose minimal for this lab
    • Disk / Memory / Processors — the defaults are fine to start
  3. Submit and wait for the status to show running.

Note your Server ID — everything below depends on it.

B2. Connect to your virtual server

Your SSH port is 2000 + ID. For example, server ID 474 → port 2474.

ssh yourusername@myserver.doc.gold.ac.uk -p <2000+ID>

From off-campus, you can instead tunnel through the SSH proxy using just your ID:

ssh -t yourusername@igor.gold.ac.uk myserver ssh <ID>

Host key warning? If your VM was re-provisioned with the same ID, SSH may warn that remote host identification has changed. Remove the old entry from your known_hosts file using ssh-keygen -R "[myserver.doc.gold.ac.uk]:<2000+ID>" (or on igor if connecting via the tunnel).

B3. Set up your files and run Python’s static server

Create your public_html folder and index.html file on your VM:

mkdir -p ~/public_html
cd ~/public_html
nano index.html

Paste your HTML content (personalize it if you’d like):

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>VM Static Page</title>
</head>
<body>
  <h1>Hello from my personal virtual server!</h1>
  <p>This is a static page served directly by Python.</p>
</body>
</html>

Now, serve the contents of this directory on port 80:

sudo python3 -m http.server 80

Why sudo? Ports below 1024 are privileged in Unix-like systems. Binding to standard HTTP port 80 requires administrative privileges.

B4. View it in a browser

From off-campus (or anywhere via the HTTP proxy):

<http://www.doc.gold.ac.uk/www/<ID>/>

(Be sure to include the trailing slash / after your ID; do not add port numbers to the proxy URL).

From on-campus, your web port is 8000 + ID:

<http://myserver.doc.gold.ac.uk:<8000+ID>/>

Checkpoint: You should see your static page. Look at your terminal: Python logs incoming HTTP requests in real time. Press Ctrl+C to stop the server when you are ready to move on.

Part C: Making it dynamic

So far, every page has been a file sitting on disk — the server just reads it and sends it back unchanged. That’s a static page. A dynamic page is generated by a running program each time it’s requested, so the content can change based on time, input, or state.

You have root on your virtual server, so you can run your own script listening on any port and construct responses programmatically.

C1. A minimal dynamic server in Python

Copying and pasting Python code into terminal editors like nano often mangles the indentation, which causes IndentationError crashes.

To avoid this, copy and run the entire block below directly into your SSH terminal from your home directory (cd ~). The cat << 'EOF' construct writes the script verbatim to disk with all indentation intact:

cat << 'EOF' > dynamic_server.py
from http.server import BaseHTTPRequestHandler, HTTPServer
from datetime import datetime

visit_count = 0

class DynamicHandler(BaseHTTPRequestHandler):
    def do_GET(self):
        global visit_count
        visit_count += 1
        now = datetime.now().strftime("%Y-%m-%d %H:%M:%S")
        html = f"""<!DOCTYPE html>
<html>
<head><title>Dynamic Page</title></head>
<body>
    <h1>This page is generated by Python!</h1>
    <p>Server time: {now}</p>
    <p>Visitor count: {visit_count}</p>
</body>
</html>"""
        self.send_response(200)
        self.send_header("Content-type", "text/html; charset=utf-8")
        self.end_headers()
        self.wfile.write(html.encode("utf-8"))

if __name__ == "__main__":
    server = HTTPServer(("0.0.0.0", 8000), DynamicHandler)
    print("Serving on 0.0.0.0:8000...")
    server.serve_forever()
EOF

Run it:

python3 dynamic_server.py

C2. View it in a browser

This is running on your user port (58000 + ID from on-campus, or /usr/<ID>/ via the proxy):

<http://www.doc.gold.ac.uk/usr/<ID>/>

Refresh the page a few times. Notice:

  • The time updates on every request — the server computes it fresh each time.
  • The visitor count goes up — the server holds state in memory between requests.

Compare this to index.html from Part B, which never changes no matter how many times you reload it.

C3. Activity — extend it yourself

Open dynamic_server.py with nano dynamic_server.py (or edit locally and use cat << 'EOF' > dynamic_server.py).

Pick at least two of the following challenges to implement:

  1. Random Dynamic Greeting: Use Python’s built-in random.choice() to pick from a list of greetings or quotes so visitors see a different one on every page refresh.

    • Reference: Python random module documentation

  2. Client Headers & Browser Fingerprinting: Read incoming HTTP headers using self.headers. Read self.headers.get('User-Agent') to report the user’s browser, or self.client_address[0] to echo their IP address back to them.

    • Reference: MDN HTTP Headers Reference
    • Reference: Python BaseHTTPRequestHandler documentation

  3. Live Server Diagnostics: Use the standard Python platform and os modules to read OS details and CPU load averages (os.getloadavg()). Display real-time machine stats directly in your HTML.

  4. Query String Parsing & Personalized Greeting: Parse self.path using urllib.parse.urlparse and urllib.parse.parse_qs. If a user accesses /usr/<ID>/?name=Sam&theme=dark, greet them by name and inject a dark CSS theme dynamically.

  5. External API Mashup: Use Python’s built-in urllib.request and json libraries inside do_GET to fetch data from an open, keyless API and embed it in your response:

    • Chuck Norris Jokes: <https://api.chucknorris.io/jokes/random>
    • ISS Current Location: <http://api.open-notify.org/iss-now.json>
    • Public Free APIs Directory: public-apis GitHub repository

  6. Multi-route Router: Inspect self.path. Return an HTML dashboard on /, a dedicated /about page, a JSON status object ({"status": "ok", "uptime": ...}) with application/json headers on /api/status, and an explicit 404 Not Found page with a 404 status code (self.send_response(404)) for any other route.

    • Reference: MDN HTTP Response Status Codes

  7. File-backed Guestbook (Persistent State): Global variables reset whenever the server restarts. Add an HTML <form action="/sign" method="GET"> with a text input. When submitted, append the message to a local file (guestbook.txt) using standard Python file I/O, read all previous entries, and render them as an unordered list (<ul>).

    • Reference: MDN HTML Form Basics

Keep Ctrl+C handy to stop the server between edits, and remember to restart it (python3 dynamic_server.py) to see your changes — unlike file-based serving, your running Python process only reflects code loaded at launch.
